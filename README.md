# go-learning

Учебный репозиторий: 40-дневный интенсив по Go после освоения синтаксиса.

Цель — не пройти туториалы, а научиться писать многопакетные CLI-утилиты и HTTP-сервисы: интерфейсы, потоковый ввод-вывод, обработка ошибок, конкурентность, тесты.

**Прогресс:** 21 / 40 дней · фаза 3 из 6

## loganalyzer

Анализатор access-логов. Читает файл, директорию или stdin, разбирает строки в структуры, агрегирует статистику и печатает отчёт в одном из трёх форматов.

Чтение потоковое: файл обрабатывается построчно, потребление памяти не зависит от его размера. На 500 МБ куча держится в пределах сотен килобайт. Битые строки не прерывают обработку — они считаются отдельно, первые десять попадают в отчёт с номерами строк.

### Запуск

```bash
go run ./cmd/loganalyzer [флаги] <файл|директория>
go run ./cmd/loganalyzer [флаги]              # чтение из stdin
cat access.log | go run ./cmd/loganalyzer
```

Если указана директория, она обходится рекурсивно, берутся все файлы с расширением `.log`.

### Флаги

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-format` | `text` | формат вывода: `text`, `json`, `csv` |
| `-top` | `0` | размер топов URL и IP; `0` — все |
| `-out` | `-` | путь для вывода; `-` — stdout |
| `-from` | — | начало диапазона, формат `2026-08-01` |
| `-to` | — | конец диапазона; указанный день включается целиком |

Даты разбираются в локальной зоне. `-from=2026-08-01 -to=2026-08-01` даёт ровно одни сутки.

### Формат входа

Строки в стиле Apache combined:

```
192.168.1.1 - - [01/Aug/2026:00:00:00 +0300] "GET /api/users HTTP/1.1" 200 1234 0.045
```

Поля: IP, время в скобках, метод, URL, протокол, статус, размер ответа в байтах, длительность в секундах. Разбор строгий: отклонение от формата делает строку битой.

### Примеры вывода

```
$ go run ./cmd/loganalyzer -top=3 testdata/logs/b.log
Total lines:  200
Broken:       0

Status codes:
  200  113
  301  29
  404  29
  500  29

Top URLs:
  /             73
  /about        7
  /admin/panel  7

Top IPs:
  1.1.1.1    10
  10.0.0.42  10
  10.0.1.15  10

Duration:
  Average:  0.064 s
  p95:      0.097 s
```

```
$ go run ./cmd/loganalyzer -format=json -top=1 testdata/logs/b.log
{"total":200,"broken":0,"by_status":{"200":113,"301":29,"404":29,"500":29},
 "top_urls":[{"key":"/","count":73}],"top_ips":[{"key":"1.1.1.1","count":10}],
 "avg_duration_sec":0.064,"p95_duration_sec":0.097}
```

CSV выводится в длинном формате `section,key,value` — три фиксированные колонки, чтобы вложенные данные отчёта уложились в валидную таблицу:

```
$ go run ./cmd/loganalyzer -format=csv -top=1 testdata/logs/b.log
section,key,value
summary,total,200
summary,broken,0
status,200,113
status,301,29
url,/,73
ip,1.1.1.1,10
duration,avg_sec,0.064
duration,p95_sec,0.097
```

### Замечания по реализации

Парсер существует в двух версиях: `ParseLine` на регулярном выражении и `ParseLineManual` на ручном разборе через `strings.Cut`. В работе используется вторая — она быстрее в 4 раза и не выделяет память (1140 → 290 ns/op, 2 → 0 allocs/op). Первая оставлена как исполняемая спецификация формата; fuzz-тест постоянно сверяет их поведение.

`p95` считается методом ближайшего ранга и требует всех значений в памяти — единственное место, где потребление растёт линейно (около 40 МБ на 5 млн записей).

## loggen

Генератор тестовых логов. Нужен, чтобы получить данные для примеров, бенчмарков и проверки поведения на больших объёмах.

```bash
go run ./cmd/loggen -lines=200 -out=testdata/logs/b.log
go run ./cmd/loggen -lines=1000 -broken=10 -out=testdata/edge/broken.log
go run ./cmd/loggen -long=2097152 -out=testdata/edge/longline.log
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-out` | `testdata/big.log` | путь к создаваемому файлу |
| `-lines` | `10` | количество строк |
| `-broken` | `0` | процент намеренно испорченных строк |
| `-long` | `0` | вместо лога записать одну строку длиной N байт |

Данные неоднородны: `/` получает около трети запросов, статусы распределены с преобладанием `200`, каждая тысячная запись содержит выброс по длительности. Флаг `-long` нужен для проверки лимита буфера `bufio.Scanner`.

Файлы `testdata/**/*.log` не версионируются — необходимо сгенерировать их перед запуском примеров.
